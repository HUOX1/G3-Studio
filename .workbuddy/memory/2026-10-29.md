## G3 启动小窗口（64×64）专项排查

- 产出：`docs/G3_启动小窗口排查报告.md`（阶段一，只读分析，未改源码）
- 关键结论（已用本机 4.7.2 二进制 + 4.7.2-stable 源码验证）：
  - 64×64 不是 G3 设的：`scene_tree.cpp:2069 root->set_min_size(Size2i(64,64))` 是引擎硬下限，`project.godot` 的 `override=1` 被 `_update_window_size()` 抬到 64。实测 override=1/32→64，100→100。
  - G3 的启动窗口配置是官方文档 "Hiding the window during the splash screen" 的逐条照抄；唯一实质偏离是**恢复时机**：官方在 Autoload `_enter_tree`+1 帧，G3 在 `main.gd:292/300-312` 用 `call_deferred`+3 帧，导致 UI 先在 64×64 上 present（日志空档 34~100ms）。
  - 透明本身有效（ctypes+GDI 抓屏实测：64×64 区域像素=桌面像素）；黑/青来自 `main.cpp:3459 show_window()` 之后、首帧 present 之前的内容未定义期，颜色随后端变化，故"换渲染器只改颜色"。
  - `unfocusable=false` 在 `main.gd:269`（UI 构建前）就执行 → 过早。
  - `timeout_force_reveal` 无副作用（`main.gd:328` guard 先返回），仅日志噪音；计时器从未 stop。
  - `NativeWindowGate` 100% 初始化失败：`startup_splash.py:117` 用了不存在的 `ctypes.wintypes.WNDENUMPROC`（g3.log 4 次同栈），外部遮罩形同虚设。
- API 核对（4.7.2）：`DisplayServer.window_set_visible` 不存在；主窗口 `Window.visible=false` 被引擎拒绝（window.cpp:1017）；配置级屏外坐标会被 OS 收敛，运行时 `position` 不被钳制。
- 建议方案：首选"离屏预热 + 就绪后一次性归位"（不依赖透明/小窗）；备选"只压缩暴露期到同帧"。
- 探针与源码副本都放在 `%TEMP%\g3probe`，未写入项目。
