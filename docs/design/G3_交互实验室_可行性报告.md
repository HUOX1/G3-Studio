# G3 内置交互实验室｜第一步可行性报告

> 阶段：只读调查（未修改任何代码或资源）
> 日期：2026-10-29
> 结论：**可行，风险低**。COMICS 分区是唯一真正的空壳，改造成本约 **1 个新文件 + main.gd 6 行**。

---

## 0. 结论摘要

1. **空白分区只有一个：COMICS**。它当前的全部实现是一个 `Label`（`main.gd:519-525`、`1063`），没有任何业务逻辑、数据依赖或信号。
2. **MUSIC 不能当实验室**——它已有 874 行的 `archive_gallery.gd` 实体模块，动了就是重构。
3. **UISfx 不能直接复用 `play(id)`**：id 是封闭枚举（`ui_sfx_manager.gd:18`），加候选 id 等于改正式常量。但可以**按名字复用它创建的 `UI` 总线**，并读取它的 `enabled` / `volume`——零耦合。
4. **候选音频放在用户目录**（`%LOCALAPPDATA%\G3\lab\sfx\`），扫描加载，正式三个 WAV 一个字节都不用动。
5. 动画模拟成本约 **60 行**：复制 14 行贝塞尔求解器 + 一张卡片 + 一个 Tween，参数与正式一致但常量独立定义。

**关键判断**：真正能"直接复用"的是**总线 + 加载器 + 缓动算法**，而不是 UISfx 的播放接口。把候选塞进 UISfx 反而会把实验变量污染到正式模块里。

## 4. 候选 WAV 怎么播而不覆盖正式音效

### 4.1 存储位置

```
%LOCALAPPDATA%\G3\lab\sfx\*.wav
```

**理由**：

- `%LOCALAPPDATA%\G3\assets` 已被 `g3_core/paths.py:35` 定义为正式数据目录（当前为空），语义上不该塞实验素材
- 独立 `lab/` 子目录，删除即清空，不污染仓库、不进 Git
- 首次进入实验室时用 `DirAccess.make_dir_recursive_absolute()` 自建（4.7.2 已核对存在）

### 4.2 播放路径

```
实验室自有 AudioStreamPlayer（1 个）
  ├─ bus = "UI"（取不到就退回 Master）
  ├─ stream = AudioFileLoader.load_audio(该文件绝对路径)
  ├─ volume_db = -18 + linear_to_db(UISfx.volume)   # 与正式音效同一套换算
  └─ play() 之前先 stop()                            # 单播放器，天然不叠加
```

### 4.3 为什么不会覆盖正式音效

| 正式对象 | 实验室是否触碰 | 依据 |
|---|---|---|
| `UISfx` 的 3 个 player | ❌ 不触碰 | 实验室用自己的 player，不调 `UISfx.play()` |
| `SFX_FILES` / `SFX_GAIN_DB` 常量 | ❌ 不修改 | 不在常量里加 `lab` 键 |
| `assets/audio/ui_*.wav` | ❌ 只读 | 候选文件在用户目录，与仓库文件物理隔离 |
| `settings.json` | ❌ 不写 | 实验室参数只存内存（本轮明确不做预设管理） |

### 4.4 正式音效的 A/B 对照（只读）

为了让"偏卡通"的判断有参照，实验室**只读列出**三个正式音效（`boot` / `detail_in` / `detail_out`），标注「正式」，点击时调用 `UISfx.play(id)`。

这是**唯一**会碰到 UISfx 的地方，且只调用它的公开方法、不改变任何状态。副作用：`UISfx` 自身有 160ms/120ms 节流，正好顺带验证节流是否有效。

## 5. 动画模拟成本

### 5.1 正式详情动画的实现（供对照）

```gdscript
# game_section.gd:173-174
const DETAIL_F_DURATION: float = 0.50
const DETAIL_F_START_SCALE: float = 0.97
# game_section.gd:2345-2352  _detail_f_enter_frame()
_grid_scroll.modulate.a  = 1.0 - t      # 海报墙淡出
_detail_view.modulate.a  = t            # 详情淡入
_detail_view.scale       = lerp(0.97, 1.0, t)
# 缓动：cubic-bezier(.22,.78,.2,1)  → 见 _hover_css_bezier()
```

### 5.2 实验室的最小复刻

| 环节 | 做法 | 行数 |
|---|---|---|
| 卡片 | `ColorRect` 320×180 + 两行 `Label`（标题/说明），不加载任何封面 | ~25 |
| 展开 | `Tween.tween_method(_step, 0, 1, 0.50)`，`_step` 内改 alpha + scale | ~15 |
| 收起 | 同一条曲线反向，起点取**当前 alpha**（与正式实现一致，支持中途反向） | ~10 |
| 缓动 | 复制 `_hover_css_bezier` 14 行 | ~18 |
| 循环预览 | 可选，用 `tween.finished.connect()` 再起一轮，开关可控 | ~10 |

**合计约 78 行**，全部在实验室内部，不引用 `game_section` 的任何成员。

### 5.3 一个必须说明的精度限制

Godot 的 `Tween.set_trans()/set_ease()` **没有** CSS cubic-bezier 预设。要做到与正式动画一致，只能像 `game_section` 那样用 `tween_method` 逐帧回调自定义曲线——**这也是复制的 14 行求解器的用途**。若将来正式动画改成 `TRANS_CUBIC/EASE_OUT`，实验室必须同步，否则对照失效。报告里把这条列为风险 R3。

## 6. 防叠加 / 防残留 / 防泄漏

| 风险 | 措施 |
|---|---|
| 连续点击导致音频叠加 | **单播放器**，`play()` 前必 `stop()`；候选切换时 `stop()` + 换 stream |
| 重复展开导致 Tween 叠加 | 只保留一个 `_anim_tween` 引用；起新动画前 `if _anim_tween != null and _anim_tween.is_valid(): _anim_tween.kill()` |
| 切分区后音还在响 | `set_active(false)` 内 `stop()`；由 `_apply_section_now` 调用 |
| 切分区后 Tween 还在跑 | 同上，`kill()` 并 `_anim_tween = null` |
| 音频流泄漏 | 候选流只存在 `_streams: Dictionary` 里，切目录/切候选时整表替换；`AudioStream` 是 `RefCounted`（已核对 `inherits=AudioStream`），引用归零自动释放 |
| 节点泄漏 | 实验室节点**常驻不销毁**，只切 `visible`；不反复 `new()`/`queue_free()` |
| 异常文件 | `load_audio()` 返回 `null` 直接跳过，不 `push_error` 打断 |
| 目录不存在 | `DirAccess.make_dir_recursive_absolute()` 后重扫；失败则显示提示文案 |

`Tween.kill()` / `is_valid()`、`DirAccess.get_files_at` / `make_dir_recursive_absolute` 均已在本机 4.7.2 的 `extension_api.json` 中核对存在。

## 7. 隔离边界

| 维度 | 允许 | 禁止 |
|---|---|---|
| 音频 | 自建 player 播候选；调 `UISfx.play(id)` 试听正式音 | 改 `UISfx` 任何常量/状态；覆盖 `assets/audio/*` |
| 动画 | 实验室内自有 Tween + 复制的缓动 | 调 `game_section` 的任何方法；改 `DETAIL_F_*` |
| 启动 | 无 | 触碰 `_start_startup_veil` / 遮幕 / 图标 / `project.godot` 启动项 |
| 导航 | 复用 COMICS 现有条目 | 改 `XMB_SECTIONS`、`CONTENT_SECTIONS`、抽屉逻辑 |
| 持久化 | 无（内存） | 写 `settings.json`、写 `library.db` |
| 作用域 | 只写自己子树 | 写 `_ui_root` 其它子节点、`window_chrome`、主题控制器 |

**一句话：实验室对外只有三个只读依赖——`UI` 总线名、`UISfx.enabled/volume`、`audio_file_loader.gd`。任何参数调整都出不了自己的节点。**

## 13. COMICS CRT 动画实验页演进（2026-10-30 起）

第一阶段报告中的 COMICS 空壳已由交互实验室接管；本节记录新增的第三个独立实验页。原报告中的音效页、图标页和音效隔离结论仍然有效，以下为新增能力与边界。

### 13.1 真实游戏卡片样本

- `game_section.gd` 暴露只读 `get_animation_lab_samples(max_count=6)`，从当前海报墙卡片中读取已解码的 `TextureRect.texture`，返回 `id`、`title`、`platform`、`texture`。
- 封面纹理完成标准解码或插件加载、以及游戏列表排序 / 搜索重建时，发出 `lab_cover_samples_changed`；`main.gd` 把最新快照传给实验室。
- 实验页最多显示 6 张真实封面副本，按实验页宽度自适应列数并保持 2:3 比例。素材尚未解码时显示等待状态，纹理就绪后自动补齐；不以 ColorRect 或渐变占位图替代封面。

### 13.2 Experiment A：完整 CRT / VHS 入场动画

旧 V16 的四种荧光体模式、四档旧强度、旧静态预览和旧 VHS 开关已从实验页移除。当前 Experiment A 不再是静态封面上的循环扫描，而是一段有明确起伏、独立效果包络和最终清洁帧的单次入场动画。

| 参数 | 控制内容 | 默认值 |
|---|---|---:|
| 通电爆发 | 中心白色亮核、水平能量线及青 / 品红辉光 | 1.85 |
| 颗粒显色强度 | RGB 荧光颗粒对原图的亮度 / 色彩响应；不改变透明度、颗粒数量或排列间距 | 0.72 |
| 展开边缘磷光 | 通电亮线向上下显像边缘交接时的白色核心与青 / 品红荧光晕 | 1.55 |
| 信号故障 | 两次 VHS 横向撕裂、扫描线组错位和 RGB 分离 | 0.92 |
| 扫光强度 | 颗粒化光栅核心、颗粒激发与光带亮度 | 1.35 |
| 光带宽度 | 按卡片尺寸计算的基础光带宽度倍率 | 1.00 |
| 锁定高光 | 从左向右通过封面的信号锁定亮带 | 1.15 |
| 颗粒余辉 | 光栅经过后短暂保留的空间衰减尾迹 | 0.55 |
| 噪声破碎 | Value Noise 与单元噪声对光栅颗粒的调制程度 | 0.38 |
| 扫描速度 | 调整单次垂直光栅推进曲线，不改变入场总时长 | 0.78 |

每张卡片独立执行 960ms 时间轴，相邻卡片按 130ms 错峰启动，最多 6 张卡片交叠播放，完整队列约 1.61s。各效果并非简单串联，而是在有明确主次的时段内短暂重叠：

| 单卡时间 | 阶段 / 事件 | 视觉表现与生命周期 |
|---|---|---|
| 0–101ms | POWER ON 爆发 | 中央白色亮核迅速扩展成水平亮线，青 / 品红辉光短促增强后快速衰减；不是持续常亮 |
| 62–336ms | IMAGE REVEAL + EDGE PHOSPHOR | 水平亮线在展开起点仍位于画面中心，随后自然分成上下两条显像边缘；白色核心、青 / 品红荧光晕及 RGB 颗粒响应沿边缘移动，边缘在封面完全展开前衰减退出 |
| 274–343ms、389–457ms | VHS GLITCH 两次脉冲 | 两次短促横向撕裂、局部扫描线组错位与 RGB 漂移；不持续覆盖整张封面 |
| 307–730ms | PHOSPHOR RASTER | 水平光栅带从顶部向底部移动，颗粒逐点响应；扫描核心先出现，后留下独立衰减的磷光尾迹 |
| 514–758ms | SIGNAL LOCK | 一道青 / 品红纵向亮带从左向右扫过，和垂直光栅、卡片运动有控制地重叠 |
| 437–802ms | SPATIAL SETTLE | 整张卡片（封面、标题和平台文字）从下方约 24px 处向上归位，缩放由 0.97 平滑恢复至 1.0；标题信息随后淡入 |
| 749–864ms | AFTERGLOW FADE | 扫描余辉与荧光颗粒逐渐衰减；所有动态效果在单卡约 864ms 前归零 |
| 864–960ms | CLEAN HOLD | 保留完整、清晰的原始游戏封面；无颗粒遮罩、无光带、无噪点、无色散、无循环扫描 |

运动作用于卡片的独立内容层，不改变 GridContainer 的布局位置；不使用 Y 轴透视翻转。启动亮线由独立的快速爆发包络驱动，不受卡片根节点淡入压制；封面显像、两次故障、垂直光栅、横向锁定高光、空间运动和余辉分别由独立时间参数控制。扫描速度只改变光栅推进曲线，不改变 960ms 单卡总时长。

**播放为单次入场，不提供入场后循环扫描。** 最终状态由统一的 clean effect state 复位：`power_envelope`、`phosphor_activity`、`glitch_strength`、`scan_envelope`、`afterglow_envelope`、`lock_envelope` 全部为 0，`scan_progress=-1`、`reveal_progress=1`；Shader 此时直接输出原始封面纹理。停止或离开页面时同样立即复位。

### 13.3 卡片尺寸与颗粒尺度自适应

实验页复制 `game_section.gd` 的窗口缩放、侧栏宽度、网格留白、卡片分档和 2:3 比例计算，不再使用固定的 148×222 预览尺寸。窗口尺寸变化时重新计算卡片宽高，并把实际卡片尺寸传入 Shader。

| 视口尺寸 | 正式游戏卡片尺寸 | RGB 颗粒间距 |
|---|---:|---:|
| 最小窗口 1244×700 | 129.58×194.37 px | 3.20×2.40 px |
| 1920×1080 | 200×300 px | 2.83×2.16 px |
| 2560×1440 | 260×390 px | 2.51×1.95 px |
| 最大参考卡片 377px 宽 | 377×565.5 px | 1.90×1.55 px |

最小边界来自 1244×700 窗口的实际卡片布局；最大边界来自 `UI_SCALE_MAX=1.30` 与最大卡片档 290px。中间尺寸按当前卡片宽度在两个端点之间连续插值。实际全屏分辨率由运行时视口决定，实验页顶部会显示当前卡片尺寸和颗粒间距；表中 377px 是当前布局规则下的最大参考卡片，不代表所有显示器全屏都会达到该尺寸。

颗粒采用交错排列的 RGB 子像素点阵。排列结构由 Shader 固定；单颗粒显示面积通过点形状控制，当前版本将点形状边界由 0.34–0.48 收紧为 0.27–0.39，颗粒间距仍随卡片实际尺寸自适应。UI 的“颗粒显色强度”只控制 RGB 颗粒的亮度 / 色彩响应，不改变透明度、颗粒数量或排列间距；颗粒数量密度由间距决定。通电亮线与显像展开共享同一条中心轴：展开初始帧的两条边缘重合在中心亮线上，随后随中心向上下扩张的遮罩分离移动，并由独立的白色核心、青 / 品红荧光晕和 RGB 颗粒响应增强边缘。扫描时使用移动遮罩调制每个荧光颗粒的亮度，并用 Value Noise 与单元噪声打破光带的均匀性。余辉通过扫描位置之后的指数衰减尾迹计算，不保存上一帧屏幕图像。

### 13.4 生命周期与隔离

- 切出 CRT 页签或离开 COMICS 时，立即停止扫描并清除动态光带与余辉。
- 单次完整入场结束后，所有动态效果和 RGB 颗粒调制全部归零，恢复原始清晰封面；不在完成后循环扫描。
- 播放过程中若收到新的封面快照，先暂存；整组单次入场结束或用户停止后再刷新，避免中途销毁正在运动的卡片。
- 窗口尺寸变化时重新计算正式卡片尺寸与颗粒间距，并更新所有预览材质。
- 游戏样本仍由 `main.gd` 传入只读封面快照；实验页不持有 `GameSection` 引用，不启动第二套解码流程。
- 实验参数只存在内存，不写入 `settings.json` 或 `library.db`，不自动应用到正式海报墙。
- 正式 `g3_crt_signal_cover.gdshader`、`g3_crt_signal_halo.gdshader`、正式 960ms / 130ms 入场调度和正常游戏交互均不修改。
