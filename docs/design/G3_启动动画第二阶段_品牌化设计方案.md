# G3 启动动画第二阶段：品牌化启动动画设计提案

- 设计日期：2026-10-29
- 性质：**只读研究 + 设计提案**。未修改任何源码，未运行程序。
- 已验收基线：窗口固定 1244×700、Boot Splash `#0E1218`、主场景遮幕 0.45s 淡入已上线并目视通过。
- 本阶段约束：不改窗口创建与启动器、不引入外部 Splash、不加固定等待、不重构 `main.gd` 与业务模块。

## 0. 结论摘要

**先说一个必须先解决的问题：项目里没有任何 G3 品牌 Logo 资源。**

`assets/` 下只有平台图标与 3D 模型；`project.godot` 没有配置 `application/config/icon`；整个前端没有字体文件，全部走引擎默认字体。唯一存在的"品牌元素"是标题栏里那两个字：`window_chrome.gd:117` 的 `Label.text = "G3"`（13 px，默认字体，颜色取主题文本色）。

所以"G3 Logo 居中"这件事有三条路，**需要你选一条**：

| 选项 | 说明 | 我的建议 |
|---|---|---|
| **A. 字标**（复用现有字形） | 用同一个 `Label` 渲染 "G3"，放大到 ~100 px，加字距与描边。与标题栏同源，不算另立品牌 | **推荐**（零新增资源） |
| B. 你提供 Logo 图片 | 你放一张 PNG/SVG 进 `assets/`，动画直接引用 | 观感最好，但要等你出资源 |
| C. 无字标，纯光效 | 只做冷光扩散 + 背景呼吸，不放任何文字 | 最保守，品牌感最弱 |

**推荐方案（在选项 A 之上）**：方案一「同窗共存」——Logo 与光晕塞进**现有那 0.45 秒**，和遮幕同一时刻起、同一时刻灭，不新增任何等待，只改 `main.gd` 一个文件、约 38 行。

## 2. 现有遮幕实现、生命周期与层级

### 2.1 代码位置

| 内容 | 位置 |
|---|---|
| 遮幕颜色常量 | `main.gd:69` `STARTUP_VEIL_COLOR = Color(0.055, 0.070, 0.095, 1.0)` |
| 淡出时长常量 | `main.gd:70` `STARTUP_VEIL_FADE_SECONDS = 0.45` |
| 调用点 | `main.gd:273`（`_ready()` 末尾） |
| 实现函数 | `main.gd:278-297` `_start_startup_veil()` |

### 2.2 生命周期（当前）

```
_ready() 末尾
  └─ _start_startup_veil()
       ├─ CanvasLayer(layer=120) + ColorRect(PRESET_FULL_RECT, MOUSE_FILTER_STOP)
       ├─ color = STARTUP_VEIL_COLOR        ← 首帧即完全不透明
       ├─ await RenderingServer.frame_post_draw   ← 首帧画完
       └─ Tween: color:a 1→0，0.45s，SINE/EASE_OUT
            └─ 回调 layer.queue_free()      ← 整层一次性回收
```

**关键性质**：回收动作是 `layer.queue_free()`，**整层连同所有子节点一起销毁**。这意味着任何加进 layer 120 的 Logo/光晕节点都会自动跟着回收，不需要单独的清理代码，也不会留下悬空 Tween。

### 2.3 层级分布（全项目 CanvasLayer）

| 层 | 内容 | 位置 |
|---|---|---|
| 4 | 档案展厅（ArchiveGallery） | `archive_gallery.gd:73` |
| 6 | 游戏分区 UI | `game_section.gd:617` |
| 10 | 主 UI 根层（含侧栏、标题栏等） | `main.gd:381-382` |
| 110 | 分区切换遮幕 | `movie_bottom_overlay_builder.gd:62` |
| **120** | **启动遮幕（最上层）** | `main.gd:280` |

遮幕在最顶层，意味着**遮幕期间标题栏也是被盖住的**——画面上只有"深灰蓝 + 后续要加的 Logo"，本身就接近一个干净的启动画面，这对品牌动画是好事。

## 3. 三个方案

### 方案一：同窗共存（推荐）

**视觉效果**：深灰蓝底 → "G3" 由暗转亮浮起 → 一圈冷蓝光晕自字后扩散、淡出 → 字随后消隐 → 正式界面同时露出。整个过程一条 0.45 秒的"呼吸"，没有停顿。

**时间轴（总长 0.45s，与现有淡出完全重合）**

| 时间 | 字标 `modulate:a` | 光晕 `modulate:a` / `scale` | 遮幕 `color:a` |
|---|---|---|---|
| 0.00s | 0 → 1（0.14s，SINE/EASE_OUT） | 0 → 0.50（0.20s），0.80 → 1.30 | 1.00 |
| 0.14s | 1.00（保持） | 0.50 → 0（0.22s） | 0.69 |
| 0.28s | 1 → 0（0.17s，CUBIC/EASE_IN） | 0 | 0.38 |
| 0.45s | 0 | 0 | 0 → `layer.queue_free()` |

字标同步做 `scale 0.96 → 1.00`，制造"轻轻顶上来"的感觉。

**实现方式**

- 全部塞进 `_start_startup_veil()`，不新增函数、不改调用点
- 一个 `Tween` 用 `set_parallel(true)` 并行驱动三条轨，末尾 `chain().tween_callback(layer.queue_free)`
- 字标：`Label` + `"G3"` + `add_theme_font_size_override("font_size", 100)` + `add_theme_color_override("font_color", _theme_text)`，用 `CenterContainer` 居中；字距用 `FontVariation.spacing_glyph`（4.7.2 已确认存在）
- 光晕：`TextureRect` + `GradientTexture2D`（`FILL_RADIAL`，4.7.2 已确认存在），**运行时生成，不新增任何资源文件**
- 颜色取 `#618AC0`（= `game_background.gdshader` 的 `glow_color`），与现有背景光同一支

**性能成本**：1 个 Label + 1 个 256×256 纹理 + 2 个 Tween 轨道，0.45 秒后全部销毁。无每帧脚本、无 Shader 编译、无磁盘 IO。

**代价**：字标就是"G3"两个字母，排版上需要字距/描边修饰才不至于像纯文字。若你选 B（提供图片），视觉档次会明显更高。

---

### 方案二：越界延续（更强的仪式感）

**视觉效果**：同方案一，但 Logo 不在 0.45 秒结束，而是跨过遮幕淡出、**叠在已经显现的界面上**继续存在到 0.95 秒，再慢慢消隐。

**时间轴**

| 时间 | 事件 |
|---|---|
| 0.00–0.18s | 字标浮现，光晕起 |
| 0.18–0.52s | 字标保持，光晕扩散至最大后淡出 |
| 0.45s | 遮幕撤完（**界面已可见**），Logo 仍在最上层 |
| 0.52–0.95s | 字标整体消隐，`layer.queue_free()` |

**实现方式**：与方案一同一结构，只是把 Logo 轨道的时长拉长到 0.95s，遮幕轨道仍是 0.45s；`queue_free()` 由 Logo 轨道结束触发（而不是遮幕轨道）。

**性能成本**：与方案一同级。

**代价（关键）**：0.45–0.95s 这半秒里，Logo 正压在**封面入场动画**之上（见第 5 节：封面 1 在 1.0s 才播完）。等于用 Logo 换掉了开局最有辨识度的"封面翻转入场"。而且这半秒内必须给 Logo 设 `MOUSE_FILTER_IGNORE`，否则会挡住点击。

**结论**：观感更"有仪式"，但抢戏。除非你明确想要"Logo 盖着界面慢慢退"的效果，否则不推荐。

---

### 方案三：无字标纯光效（最保守）

**视觉效果**：不放任何文字。遮幕保持 0.45s，期间从画面中心扩散一圈冷蓝柔光（半径 0 → 1.4 屏），随后与遮幕一起淡去。

**时间轴**：0.00–0.30s 光晕 alpha 0→0.35、scale 0.6→1.4；0.30–0.45s 与遮幕同步归零。

**实现方式**：与方案一相同，只是去掉 Label 与 CenterContainer，只剩 1 个 TextureRect。

**性能成本**：三者中最低（1 个节点）。

**代价**：没有品牌字标，"G3 的感觉"完全靠配色与节奏传达。适合"先验证节奏、后补字标"的分步走。

## 4. 如何在不破坏现有 0.45 秒淡入的前提下加入 Logo

四条硬性技术约束，全部来自现有实现：

1. **共用同一个 CanvasLayer(120)、同一个 Tween、同一个回收点。**
   不新建层、不新建 Tween、不单独 `queue_free()`。这样 Logo 的生命周期天然被遮幕的回收动作覆盖，不会多出一行清理代码。

2. **Logo 必须从 `modulate:a = 0` 起。**
   首帧（`frame_post_draw` 之前那一帧）屏幕内容必须仍是纯色 `#0E1218`——这是上一阶段验收过的"首帧唯一色数 = 1"。只要 Logo 初始 alpha 为 0，首帧结论不变。

3. **不要在 Logo 上再 `await` 任何东西。**
   现有代码只在 `_ready` 末尾 `await RenderingServer.frame_post_draw` 一次；Logo 的所有动画都必须由那之后的同一个 Tween 驱动。任何额外 await 都会引入新的帧等待，等于变相增加启动耗时。

4. **并行轨要显式 `set_parallel(true)`，末尾 `chain()` 回收。**
   `Tween` 默认是串行的，三条轨若不加 `parallel` 会变成 0.45+0.14+0.20+0.17 的叠加，直接破坏 0.45 秒的总长。正确写法是并行驱动，总长取最长轨（0.45s），最后 `chain().tween_callback(layer.queue_free)`。

**一个容易踩的坑**：字标用 `CenterContainer` 居中时，若把 `Label` 直接设为 `FULL_RECT` 再靠 `horizontal_alignment` 居中，字会随窗口宽度居中；但如果窗口在这一帧还没定尺寸（虽然实测启动即 1244×700），建议用 `CenterContainer` + 固定光晕尺寸，避免出现"字偏在角落"。这也是上一阶段"遮幕只有局部大小"那个坑的同源问题。

## 5. Logo 动画与封面入场动画的时序关系

封面入场参数（`game_section.gd:2861-2862`）：

```
每张封面入场时长：1000 ms
相邻封面起始间隔：180 ms
起始时刻：首次 _rebuild_grid 所在帧（= 第 1 帧，与遮幕同帧）
```

于是第 1 帧之后各封面的进度：

| 时刻 | 封面 1 | 封面 2 | 封面 3 |
|---|---|---|---|
| 0.45s（遮幕消灭） | 45% | 15% | 未开始 |
| 0.95s | 95% | 65% | 35% |

**结论**：

- **方案一（Logo 0.45s 结束）**：Logo 退场的那一刻，封面 1 正好播到一半、封面 2 刚起步。观感是"字退下去，墙正在拼起来"，两段动画首尾相接、互不遮挡。**这是最优分界点**，而且它恰好等于现有淡出时长——不需要改动任何参数。
- **方案二（Logo 0.95s 结束）**：Logo 会完整吃掉封面 1 的入场（0–1.0s），得不偿失。
- **原则**：Logo 总时长 ≤ 0.45s 时不遮挡封面入场；超过 0.45s 就开始抢戏。

## 6. 边界情况与异常处理

| 场景 | 行为 | 是否需要额外代码 |
|---|---|---|
| **快速启动**（热缓存，`_ready` 仅 ~0.4s） | 动画是**时间驱动**而非加载驱动，表现与慢启动完全一致；遮幕本来就要 0.45s，Logo 塞进去不额外占用时间 | 否 |
| **慢启动**（首帧晚到） | 遮幕与 Logo 都在 `frame_post_draw` 之后才开始，启动再慢也只是"纯色画面停留更久"，动画本身不变 | 否 |
| **启动中关闭窗口**（Alt+F4 / 点关闭） | 遮幕、Logo、Tween 全部随场景树销毁；Tween 绑定节点，节点没了 Tween 自动失效，无报错、无残留 | 否（现有机制已覆盖） |
| **启动中触发分区切换** | 遮幕层 120 盖住 UI(10) 与分区遮幕(110)，且 `MOUSE_FILTER_STOP` 吞掉点击，0.45s 内不可能完成一次切换 | 否 |
| **不同分区启动**（games / movies / system） | Logo 与分区无关，三者的表现一致。唯一既有差异是"遮幕色 `#0E1218` → 各分区背景色"的色相游移，属于上一阶段已存在现象，本阶段不改善也不恶化 | 否 |
| **窗口缩放** | 遮幕 `PRESET_FULL_RECT`、Logo 用 `CenterContainer`，均随窗口自适应；且遮幕期间标题栏被盖住、无法拖拽缩放 | 否 |
| **用户开了"减少动态"**（若将来引入） | 本方案未接该系统设置；如需要，可在检测到后把 Logo 轨道时长压到 0.12s | 需一行判断（本阶段不做） |

## 7. 最小改动清单、撤销方案与验收标准

### 7.1 改动清单（以方案一 + 选项 A 字标为例）

| 文件 | 改动 | 规模 |
|---|---|---|
| `g3_frontend/scripts/main.gd` | `_start_startup_veil()` 内新增：字标 Label、光晕 TextureRect、并行 Tween 轨道；新增 3 个常量（字标字号、光晕色、光晕直径） | 约 **+38 行**，1 个文件 |

**不改动**：`project.godot`、`window_policy.gd`、`game_section.gd`、`movie_wall.gd`、任何 shader、启动器、WebSocket、遮幕的现有两行常量与 0.45 秒参数。
**不新增**：任何图片、字体、shader 文件（光晕用 `GradientTexture2D` 运行时生成）。

### 7.2 撤销方式

方案一的所有新增内容都在 `_start_startup_veil()` 函数体内 + 3 个常量。撤销 = 删掉函数内新增的节点构建与 Tween 轨道、删掉 3 个常量。**遮幕本身的两行常量和 `_ready()` 调用点完全不动**，所以撤销后必然回到当前已验收状态。

### 7.3 验收标准

| # | 标准 | 判定方法 |
|---|---|---|
| 1 | 首帧仍是纯色 `#0E1218`，唯一色数 = 1 | 启动瞬间对窗口截图统计唯一色数（沿用上一阶段的 PrintWindow 方法，**位图必须与窗口同尺寸**） |
| 2 | Logo 在首帧不可见（从 alpha 0 起） | 同上，首帧不应出现字标像素 |
| 3 | 0.45s 时刻 Logo 与遮幕同时消失 | 采样序列中，Logo 最后可见帧与遮幕归零帧相差 ≤ 2 帧 |
| 4 | 启动总时长不变 | 从窗口可见到界面可交互的时间与当前版本相差 ≤ 50 ms |
| 5 | 三个分区启动表现一致 | games / movies / system 各启动一次 |
| 6 | 不遮挡封面入场 | 0.45s 后画面上不再有 Logo 像素，封面入场可见 |
| 7 | 无新增资源文件 | `git status` 在 `assets/` 下无新增 |
| 8 | 中断无异常 | 动画期间关闭窗口，`g3.log` 无 WARNING/Traceback |
| 9 | 可撤销验证 | 删除新增代码后，行为与当前版本逐帧一致 |

## 8. 需要你决定的三个问题

1. **Logo 用哪种形态？** A 字标（复用现有 "G3" 字形，立即可做）／ B 你提供图片（观感最好，需等资源）／ C 无字标纯光效（最保守）。
2. **要方案一还是方案二？** 方案一不遮挡封面入场；方案二仪式感更强但会压住开局的封面动画。
3. **字标颜色与光晕色**：建议字标取 `_theme_text`（近白 `0.93,1,1`）、光晕取 `#618AC0`（与游戏背景光同色）。若你想要更"冷/更亮"的观感，给个方向我再调。
