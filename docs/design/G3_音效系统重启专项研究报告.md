## 0. 结论摘要

四句话说完：

1. **项目里没有任何音频文件**（wav/ogg/mp3 全零），**没有任何 Audio Bus 配置**，**没有任何 `.tres`**。所谓"重启音效系统"，实际是从零起步，而不是复活旧代码。
2. 但**不是从零能力**：已有 `AudioStreamPlayer`（主题音乐）、`audio_file_loader.gd`（wav/ogg/mp3 三分支加载器）、以及完整的"开关 + 音量"设置范式。这三样可以直接复用。
3. **详情页进入/退出的音效不需要碰 `game_section.gd`**：`game_theme_requested` / `game_theme_cleared` 两个信号已经在 `main.gd:405-406` 连好，且分别在 `_enter_detail()` / `_exit_detail()` 内发射。这是本次审计最有价值的发现，把"最贵的两个音效"变成加两行。
4. 真正的成本不在播放，而在**音效素材**和**开关落点**：项目至今没有任何音频设置 UI，"全局静音"只能走设置文件 + 快捷键。原型阶段建议只做 3 个音效（启动、详情进、详情出），卡片确认音效需要新增一个信号，放到第二阶段。

**推荐架构**：`UISfx` Autoload（项目首个 autoload）+ 运行时创建的 `UI` 总线 + 预加载。原型总改动 **2 个新文件 + 4 处编辑**，约 150 行。

## 2. 交互触发点审计

原则：**绑定到"状态确定变化"的函数，不绑定鼠标事件**。下表的"接入成本"是相对当前代码的**净改动量**。

### 2.1 GAMES 分区（主战场）

| 交互 | 真实状态变更函数 | 行号 | 现成信号 | 接入成本 |
|---|---|---|---|---|
| 卡片点击（按下即有反馈） | `_on_grid_input` 内的 E 材质反馈块 → `create_tween(...0.36)` | `game_section.gd:2178-2185` | ❌ **无信号** | **需在 `game_section.gd` 加 1 行 `emit`**（原型阶段暂缓） |
| 卡片点击 → 选中 | `_select_index()` | `game_section.gd:2623` | ✅ `selection_changed`（第 2638 行 emit）但 **main.gd 未连接** | 加 1 行 `connect`，但**与详情进入同帧**，会撞音 |
| 点击反馈完成 → 进详情 | `_click_e_complete()` | `game_section.gd:2203-2211` | — | 不必单独接 |
| **详情页进入** | `_enter_detail()` | `game_section.gd:2240` | ✅ `game_theme_requested`（第 2268 行 emit）**已在 `main.gd:405` 连好** | **0 行**（只在 `_on_game_theme_requested` 加 1 行播放） |
| **详情页退出** | `_exit_detail()` | `game_section.gd:2280` | ✅ `game_theme_cleared`（第 2300 行 emit）**已在 `main.gd:406` 连好** | **0 行 + 1 个守卫**（见下） |
| 详情页退出（ESC） | `_unhandled_input` → `_exit_detail()` | `game_section.gd:2645-2650` | 同上 | 无需额外处理 |

**关键坑（已证实）**：`game_theme_cleared` 有**两处**发射点——第 2270 行（`_enter_detail` 中，当 `item_id` 为空时）和第 2300 行（`_exit_detail` 中）。若直接把退出音效挂到 `main.gd:2184` 的 `_on_game_theme_cleared()`，**进入一个无主题 ID 的游戏时会误播退出音**。

**守卫方案**：`main.gd:2190` 的 `_on_game_theme_palette_changed()` 已有先例（用 `game_section.is_detail_open()` 判空）。退出音效同样加 `if not game_section.is_detail_open(): return`——第 2300 行发射时 `_detail_view` 尚未隐藏（`_detail_f_exit_complete` 才隐藏），第 2270 行发射时 `visible` 已为 `true`……

等一下，这两处 `visible` 都为真，守卫条件需要修正：

- 第 2268/2270 行（进入路径）：此时 `_detail_view.visible = true`（第 2257 行已设）
- 第 2300 行（退出路径）：此时 `_detail_view.visible` 仍为 `true`（尚未执行 `_detail_f_exit_complete`）

**结论：`is_detail_open()` 无法区分进入与退出。** 必须换守卫——用 `_detail_f_exiting` 标记，但它是 `game_section` 的私有变量。

**因此退出音效的正确接法是**：在 `game_section.gd:2300` 旁边加一行专用信号 `detail_exit_requested.emit()`，由 `main.gd` 连接。这是**唯一需要触碰 `game_section.gd` 的非零改动**，但只加 1 行、不改任何既有逻辑。

> 这一条是本报告推翻了自己最初判断的地方，如实记录：`game_theme_cleared` **不能**同时充当"进入无主题"和"退出"的事件源。

## 3. 推荐架构

### 3.1 形态选择：Autoload（项目首个）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Autoload `UISfx`** | 主场景之前就绪，可在 2.1s 启动窗口内预加载；任意脚本可调；不依赖 main.gd 生命周期 | 项目此前 **0 个 autoload**，属于新增初始化阶段 | **推荐** |
| B. main.gd 内建节点 | 零 `project.godot` 改动 | 启动音必须在 main.gd 里触发；无法在 UI 构建前预加载；`game_section` 等子模块拿不到引用 | 备选 |
| C. 静态类 + 全局单例变量 | 无节点 | 仍需一个宿主节点持有播放器，绕了一圈 | 不推荐 |

**推荐 A 的理由**：启动音效的关键是**在 UI 构建（约 1 秒阻塞）期间完成 WAV 读取**。Autoload 的 `_ready` 早于主场景，正好白用这段空窗。方案 B 会让首次 `play()` 在首帧同步读盘，有卡顿风险。

### 3.2 结构

```
UISfx (Node, Autoload "UISfx")
├─ _ui_bus: int              # 运行时创建的 "UI" 总线索引
├─ _players: Array[AudioStreamPlayer]   # 小对象池，3~4 个轮转
├─ _streams: Dictionary      # id -> AudioStream，启动时预加载
├─ _last_play_ms: Dictionary # id -> 上次播放时刻，用于节流
├─ enabled: bool             # 全局开关
└─ volume: float             # UI 音量 0..1

play(id: StringName) -> void
set_enabled(value: bool) -> void
set_volume(value: float) -> void
```

### 3.3 关键设计点

**① UI 总线：运行时创建，不新增 `.tres`**

```gdscript
# 4.7.2 已核对：add_bus / set_bus_name / get_bus_index / set_bus_send 均存在
if AudioServer.get_bus_index("UI") == -1:
    AudioServer.add_bus()
    _ui_bus = AudioServer.get_bus_count() - 1
    AudioServer.set_bus_name(_ui_bus, "UI")
    AudioServer.set_bus_send(_ui_bus, "Master")
else:
    _ui_bus = AudioServer.get_bus_index("UI")
```

理由：主题音乐留在 Master，UI 音效挂 `UI`，两者音量互不干扰。`get_bus_index` 返回 `-1` 是官方约定的"不存在"信号，天然幂等。

**② 三态降级（照抄 `theme_policy.gd:24-43` 的写法）**

| 失败场景 | 行为 |
|---|---|
| WAV 文件缺失 / 解析失败 | `stream = null`，`play()` 立即 `return`，**不 push_error** |
| `UI` 总线创建失败 | 回退 `bus = "Master"`（`AudioStreamPlayer.bus` 默认值） |
| `enabled == false` | `play()` 首行 `return`，零开销 |
| 设置读取失败 | 用默认值（`enabled = true`, `volume = 0.6`） |

**③ 防重复与节流**

- **同 id 节流**：`_last_play_ms[id]`，间隔 `< 80ms` 直接丢弃（防双击、防滚轮连击、防信号重复发射）
- **同 id 不叠加**：每个 id 固定一个 player，`play()` 前先 `stop()`，保证同一音效永远只有一份
- **跨 id 限并发**：4 个 player 轮转，超出时复用最老的一个（天然丢最新的低优先级音）
- **启动音独占**：`play("boot", exclusive=true)` 会 `stop()` 全部 player

**④ 资源路径集中管理**

```gdscript
const SFX_DIR: String = "res://assets/audio/"
const SFX_FILES: Dictionary = {
    &"boot": "ui_boot.wav",
    &"detail_in": "ui_detail_in.wav",
    &"detail_out": "ui_detail_out.wav",
    &"card": "ui_card.wav",
    &"section": "ui_section.wav",
}
```

换素材 = 改一个字符串；缺素材 = 少一个键，其余照常。

**⑤ 不修改 main.gd 的模块化结构**

main.gd 只增加**离散的 1 行调用**，不新增函数、不改既有函数签名、不动任何业务逻辑：

| 位置 | 加什么 |
|---|---|
| `_start_startup_veil()`，`frame_post_draw` 之后 | `UISfx.play(&"boot")` |
| `_on_game_theme_requested()` | `UISfx.play(&"detail_in")` |
| `_on_section_fade_done()` | `UISfx.play(&"section")` |
| 新增 1 个 handler 连接新信号 | `UISfx.play(&"detail_out")` |

## 4. 声音设计

统一前提：**原创合成**，不使用 PlayStation 原版开机音效（其标志性的四音上行和弦属可识别品牌资产）。整体音色取向 = 深灰蓝 + 冷光，即"低频厚、高频薄、无金属撞击"。

| # | 声音 | 触发时机 | 建议长度 | 听觉风格 | 叠加规则 | 与视觉同步 |
|---|---|---|---|---|---|---|
| 1 | **启动唤醒** `boot` | `frame_post_draw` 之后（图标出现的同一刻） | **1.0–1.2s**（前 0.45s 是主体，尾 0.6s 是余韵） | 低频下潜（55–80Hz 正弦）＋ 三段泛音缓慢上扬 ＋ 一层极轻的高频气声。**无起音爆点**（attack ≥ 40ms），像"灯亮"而不是"开关" | **独占**：停掉所有其它音效 | 前 0.15s 与图标淡入同步；0.30–0.45s 与图标淡出、遮幕揭开同步；0.45s 后余韵落在已显示的 UI 之上 |
| 2 | **卡片确认** `card` | 点击反馈**起点**（`game_section.gd:2178` 那个 Tween 创建之前） | **60–90ms** | 木质/软塑料轻触：短促低频脉冲 + 极短高频瞬态。**必须无尾音** | 允许快速连击（80ms 节流），**不叠加**（同 id 先 stop） | 与 0.36s 的 E 材质反馈同刻起步；反馈的 23% 处（约 80ms）是按压最深点，音的瞬态应落在 0–60ms |
| 3 | **详情页进入** `detail_in` | `_enter_detail()` 发射 `game_theme_requested` 时（= 点击后 360ms） | **0.40–0.50s** | 上行：气声扫频（200→900Hz）＋ 一个纯五度上叠。开放、向前 | 不叠加；若 200ms 内重复进入则丢弃 | 与 500ms 的详情交叉淡入同起（`DETAIL_F_DURATION`），音在视觉过半时收尾 |
| 4 | **详情页退出** `detail_out` | `_exit_detail()` 第 2300 行新信号 | **0.25–0.35s** | 下行：扫频反向（700→250Hz），比进入**短 40%、轻 3dB**。收拢、向后 | 不叠加；若正在播 `detail_in` 则**先截断再播** | 与退出的反向淡出同步。刻意做短：退出是"回退"动作，音效不该抢戏 |
| 5 | **分区切换** `section` | `_on_section_fade_done()`（淡出到底、内容切换的瞬间） | **0.35–0.45s** | 带通滤波的噪声扫过（400→1600Hz）＋ 极轻的低频支撑。中性、机械感 | 不叠加；连续切换只留最后一个 | 落在 0.25s 淡出与 0.35s 淡入的接缝处，**必须短于 0.35s**，否则会压到新分区画面 |

**全局电平建议**（相对 Master 0 dB）：

| 声音 | 峰值 | 说明 |
|---|---|---|
| `boot` | **−10 dB** | 唯一允许"响"的，因为它只在启动时出现一次 |
| `detail_in` | −18 dB | |
| `detail_out` | −21 dB | 比进入更轻 |
| `section` | −24 dB | 高频操作，必须克制 |
| `card` | −20 dB | 单次极短，可略响 |

**相互关系的两条硬规则**：

1. `boot` 与其它任何音效**互斥**。启动期是"仪式"，不是"操作"。
2. `card` → `detail_in` 之间固定间隔 360ms（由既有点击反馈决定），这是天然的听觉分层，**不需要额外延迟代码**——只要别把它们接在同一帧。

## 5. 实施规划

### 5.1 原型范围（阶段一）

只做 3 个：`boot`、`detail_in`、`detail_out`。

**为什么砍掉 `card` 和 `section`**：

- `card` 需要在 `game_section.gd` 的点击反馈块里加信号发射，而那是**全项目最敏感的手感代码**（E 材质 360ms 关键帧，注释写明"Exact HTML E keyframe timing"）。原型阶段不碰。
- `section` 的接入是零成本的（1 行），但它带来的"吵"的风险最高（用户会连续切分区）。放到阶段二与"静音开关的可用性"一起验证。

**为什么 `detail_in` / `detail_out` 值钱**：一次交互跨越 360ms 反馈 + 500ms 交叉淡入，是最需要听觉锚点的动作，而它们的接入成本接近零。

### 5.2 预计修改文件清单（阶段一）

| 1 | `g3_frontend/scripts/ui_sfx_manager.gd` | **新增** | `UISfx` Autoload 全部实现 | ~130 |

### 5.3 音效素材方案（优先原创）

**推荐：程序化合成，脚本生成 WAV，零授权风险。**

| 方案 | 成本 | 质量 | 授权 | 结论 |
|---|---|---|---|---|
| **A. Python 合成 WAV**（`wave` + `math`，标准库） | 低（一次性脚本） | 中（够用，非样本级） | **完全原创** | **推荐** |
| B. 手绘/录制 | 中 | 中 | 原创 | 备选（可后期替换） |
| C. 免费音效库 | 低 | 高 | 需逐一核对许可、署名要求 | 不符合"优先原创" |
| D. 运行时 `AudioStreamGenerator` | 中 | 中 | 原创 | 不推荐：每帧 `push_buffer` 增加主线程负担，且与"启动零等待"冲突 |

**A 的具体做法**（阶段二执行，本阶段不生成文件）：

- 44.1kHz / 16-bit / 单声道，总大小控制在 **160KB 以内**
- 加法合成：基频正弦 + 2~3 个谐波（不等幅），指数包络（attack 40ms / decay / sustain / release）
- 扫频用相位累加（`phase += 2π·f(t)/sr`），避免 `sin(2πft)` 直接跳变产生咔哒声
- 首尾各加 5ms 淡入淡出，**消除 DC 爆音**
- 噪声层用固定种子 LCG 生成，保证可复现

**不做的事**：不采样 PlayStation 开机音、不采样任何游戏原声、不使用 `theme.json` 的音频通道（那是主题音乐的地盘）。

### 5.4 开关设计（三层）

| 层 | 手段 | 成本 | 阶段 |
|---|---|---|---|
| 持久化 | `settings.json` 新增 `ui_sfx: true` / `ui_sfx_volume: 0.6` | 后端 +4 行 | 一 |
| 运行时 | 快捷键 `Ctrl+M` 切换静音（`main.gd._unhandled_input` 内 1 个分支） | +5 行 | 一 |
| 可视化 | 系统页开关控件 | **中**（项目至今无任何音频设置 UI） | 三 |

**为什么快捷键而不是 UI**：全仓库搜"音乐/音量"在 `.gd` 中**零命中**——连 `theme_music` 都没有开关界面，只能手改 `settings.json`。为一个原型音效系统新建设置 UI，成本远超音效本身。`Ctrl+M` 能立刻验证"可关闭"，且不引入任何布局改动。

**注意**：`main.gd:940` 的 `_unhandled_input` 目前被 MOVIES 底栏热区逻辑占用，新增分支需放在最前面并**只在未被 handled 时响应**，避免抢走滚轮事件。

### 5.5 实施顺序（阶段一，共 7 步）

1. 生成 3 个 WAV（一次性脚本，产物入 `assets/audio/`）
2. 写 `ui_sfx_manager.gd`（含总线创建、预加载、节流、降级）
3. `project.godot` 注册 autoload
4. `settings.py` + `system_settings_controller.gd` 加两个设置项并验证 `from_dict` 不报 `Unknown settings key`
5. `main.gd` 接 3 个播放点 + `Ctrl+M`
6. `game_section.gd` 加 1 个 `detail_exit_requested` 信号 + 1 行 emit
7. **单次**启动验收（见 §7）

### 5.6 回滚方案

| 层 | 回滚动作 | 影响面 |
|---|---|---|
| 最快（不动代码） | `settings.json` 设 `"ui_sfx": false` | 全局静音，零风险 |
| 中等 | 删 `project.godot` 的 autoload 行 | 播放调用变空引用 → **需同时删 main.gd 的 3 行**，否则报错 |
| 完全 | 删 `ui_sfx_manager.gd` + `assets/audio/` + 还原 5 个文件的 diff | 回到当前状态 |

**必须备份**：`project.godot`、`main.gd`、`game_section.gd`、`settings.py`、`system_settings_controller.gd`（沿用 `.workbuddy/backups/` 惯例，带时间戳）。

## 6. 成本评估

| 项目 | 工作量 | 风险 |
|---|---|---|
| 3 个原创 WAV 合成 | 低（1 个脚本 + 调参） | 音色主观，可能需要 2~3 轮调整 |
| `ui_sfx_manager.gd` | 中（约 130 行） | 总线重复创建、节流逻辑 |
| Autoload 注册 | 极低 | **项目首个 autoload**，需确认不影响启动 |
| 设置项 + 后端校验 | 低 | 后端 `from_dict` 对未知键抛错（`settings.py:49`），字段必须与前端映射严格一致 |
| main.gd 3 处接入 | 极低 | 位置敏感（必须在 `frame_post_draw` 之后） |
| game_section 加信号 | 极低 | 触碰手感代码，但只增不改 |

**总体判断**：这是**低成本、中风险**项目。成本集中在素材，风险集中在"首个 autoload"和"设置 schema 一致性"。
