# G3 开发历史

> 记录 G3 从零到 v0.6.5 的完整演进史与关键设计决策。

---

## 1. 电影板块从零到有（2026-09-12）

**协作模式确立**：代码由 AI 编写，用户负责设计与验收。用户不懂代码，通过画设计稿和实机截图反馈指导开发。

### 1.1 设计探索
废弃了“满屏海报墙”方案，最终确定为：左列 3D 卡片轴 + 全屏暖金动态背景 + 右侧背景图（左边缘渐隐融入）。
- 电影用暖金，与游戏的冷青形成对比。
- 背景图完整显示在右侧，不裁剪、不出界。

### 1.2 混剪脚本开发（独立工具）
用户提出自动生成混剪，从 v1 折腾到 v20，**最终定位为独立工具，不集成进 G3**。
**教训**：Godot 4 核心只支持 Ogg Theora，且新版 ffmpeg 的 libtheora 与之不兼容（花屏），WebM 已被移除。任何依赖视频播放的设计必须先验证格式兼容性。

### 1.3 调试踩坑
- **抽帧亮度**：早期随机取 5 帧挑“亮度最接近 0.5”的，容易抽到转场白或模糊帧。
- **缩进错误**：Notepad++ 和 VSCode 混用导致 Tab/空格不一致。项目内必须统一用 Tab。

## 2. 电影板块打磨（2026-09-13）

- **卡片 3D 化**：选中卡从平面放大改为 **Z 轴前浮**（从队列里抽出来）。前浮后屏幕位置会偏，改用当前 Z 算 X 坐标。
- **背景图系统**：抽帧从“5 选 1”改成“抽 8 张全留”。加入 GPU 内的交叉淡入（`mix`），每 7 秒换一张。手动设置的背景图单张不轮播。
- **信息区与分区**：标题/年份右对齐在背景图上方，简介左对齐在下方。鼠标在右侧信息区时，滚轮只滚简介，不切电影。
- **光晕导航**：从右下角手柄改为顶部中间光晕，使用 `blend_add` 只提亮。

## 3. 电影板块完整化（2026-09-14，v0.6.3）

- **右键菜单**：接通编辑资料、设置封面、移除。封面同名替换时引入 `reload_covers()` 热刷新，不重建卡片保留状态。
- **播放**：接入双击播放。
- **扫描与惰性抽帧**：加入扫描库文件夹。为避免 500 部电影卡死，列表只返回数据，前端切到某部时才发 `movie.backdrop.ensure` 派发抽帧。
- **性能优化（滚动不卡）**：
  1. 后台线程读 8 张 JPG。
  2. 滚轮只标记，停止滚动 80ms 后才真正加载。
  3. Generation 检查，丢弃旧任务结果。
- **路径规范化教训**：Windows 给反斜杠，手动添加是正斜杠，导致 SQL 匹配失败重复登记。全部强制 `.replace("\\", "/")`。

## 4. 剧集与刮削器起步（2026-09-15）

- **剧集抽屉**：从 3 列网格改为纵向列表。数据存 `movie_episodes` 表。扫描器规则：1 个视频=电影，2+ 视频=剧集。支持中文季号（如“第一季”）。
- **抽帧逻辑**：改为从所有视频中随机选一集抽 8 帧。缓存有效性改用“所有集里最新的 mtime”。

## 5. TMDB 刮削器与元数据（2026-09-16，v0.6.4）

- **网络方案**：TMDB 被污染，放弃代理，改用 **UsbEAm Hosts Editor** 修改 hosts 直连。
- **只填空**：TMDB 是数据源，用户手填是覆盖层。
- **每集标题匹配（两步法）**：先按 (season, episode) 精确匹配，对不上的按顺序用展平的 TMDB 数据兜底。
- **新增 UI**：主界面加入“元数据行”（`▸ 类型 · ⏱ 时长 · ★ 评分`）；浮动窗加入毛玻璃与光带。

## 6. mpv、观看痕迹与字体系统（2026-09-17）

- **mpv 播放**：避免 PotPlayer 全屏闪烁。调用外部 mpv，G3 暂停渲染（不最小化），退出 mpv 后恢复画面。
- **全屏与缩放**：`DisplayServer` 直接调全屏。字号和间距乘 `ui_scale` 保证视觉密度一致。
- **观看痕迹**：加 `watched_seconds` / `total_seconds` / `watched_complete`。放弃铜银金分级，只看是否跨过 70%。
- **隐藏层**：右下角滚轮上滑，露出 tagline。
- **卡片特效（已废弃）**：尝试过烫金边、掠光、完成闪，视觉不满意，后续全删。

## 7. TMDB 海报与字体编辑器重构（2026-09-18）

- **海报选择**：6 路并发下载缩略图，网格墙，分页 30 张。带 `include_image_language` 参数拉全语言。
- **字体编辑器**：废弃独立窗口，内嵌 System 页，左右分栏，实时预览。下拉框只显示中文字体。
- **最大踩坑**：Godot `OptionButton` 默认 `fit_to_longest_item = true`，会被超长的英文字体名撑爆屏幕。**必须设为 false**。
- **信息区固定**：标题固定屏高 11%，简介固定 80%，切画幅不跳动。
- **透明管线排序 Bug**：麦克斯奥特曼预览图消失，因为与背景 Mesh 到相机距离接近（13.2 临界点）导致排序翻车。修法：显式设置 `render_priority`，并让 Ambient 去掉 `depth_draw_never` 回到 opaque pass。

## 8. 私有库与封面工具（2026-09-20）

- **私有库（品红库）**：给 `library_items` 加 `library_scope`。所有电影 SQL 必须带 `WHERE library_scope = ?`。长按电影图标 1.5 秒切换，独立品红主题色。
- **封面工具**：从影片出发找源封面（反向匹配噪声太大）。自动检测 DVD 封面 Front 边界，支持手动拖红线裁剪。
- **电影版块优化**：Tonemap 从 AGX 改为 LINEAR；宽画幅预览图右对齐，其余居中；卡片宽度跟随封面比例自适应。

## 13. 双缩放曲线与 WebSocket 事故（2026-10-02）

- **缩放拆轨道**：布局用 `ui_scale`（下限 0.62），字号用 `font_scale`（下限 0.90），因为小窗口字号 10.9px 看不清。
- **WS 1009 事故**：电影列表响应超过 64KB 默认缓冲导致断连死循环。修复：初始化时把 `inbound_buffer_size` 设为 8MB。
- **教训**：前端崩溃不等于数据丢，查 `library.db` 依然完好。

## 15. PSN、Rockstar 与批量管理（2026-10-15）

- **PSN 扫描**：接入 `psnawp`，用 npsso 认证。时长存独立字段 `psn_playtime_seconds`。过滤 Demo/Trial 等假游戏。支持本地覆盖文件。
- **Rockstar**：只扫描入库，不保证启动监视（主 exe 常被 Social Club 屏蔽）。
- **批量管理**：按 `B` 键进批量模式。批量刮削采用挂机逻辑——取 Steam 搜索第一个结果直接 apply。
- **文本粘贴**：支持中英双语前缀识别，多行续接简介。空字段不覆盖。
- **空壳游戏**：无启动方式的纯资料游戏排在末尾，应用 `game_card_gray.gdshader` 降饱和到 0.15，悬停回彩。
- **进程监控（三阶段）**：等出现（15 秒） -> 等消失（1.5 秒轮询） -> 确认（2 秒）。UAC 提权拿不到句柄时自动降级用 `monitor_exe` 兜底。

## 18. 游戏界面定位与空间展厅 WebP 修复（2026-10-21）

- **界面定位收敛**：游戏主版块继续使用经典海报墙；原“空间展厅”导航名称调整为“试验场”，保留为独立视觉实验入口。莱茵生命风格档案界面暂不迁移，后续再评估用于漫画/电子书版块。
- **动态封面加载**：空间展厅原先只依赖 `Image.load()`；解码失败时不回调，导致 Animated WebP 封面保留占位状态。增加失败回退，优先通过 `AnimatedImageLoader` 识别并流式播放动图，无法播放时尝试加载静态海报帧。
- **资源与性能**：动图使用小型缓存并只在对应封面可见时推进帧，避免所有历史动图在后台持续解码；原始封面、游戏数据和经典海报墙逻辑不变。
- **验证边界**：新增 Python 源码合约测试；当前容器没有 Godot 可执行程序，因此实际 GDScript 解析、Windows GDExtension 加载与渲染仍需本机验收。


## 19. 试验场退回占位与 WebP 首帧兜底（2026-10-21）

- **试验场清理**：保留导航名称和 `COMICS` 内部 ID，切入时只显示“当前仅保留模块入口”的占位提示；移除 `spatial_gallery.gd`、专属 Shader、未使用图标及相关源码合约测试，不再为该版块创建 3D 展厅或接收游戏列表。

- **藏品室兜底**：独立的游戏藏品室沿用相同的首帧兜底原则，避免解码失败后丢失封面。

## 21. 字体系统功能演进与排版体系（归档补录，2026-10-23）

## 22. 通用 Git 补丁注入器升级（归档补录，2026-10-23）

## 35. 2026-10-29｜G3 启动架构回归 Godot 标准实现，64×64 小黑窗口问题解决

- **问题背景**：此前 G3 启动时会先出现 64×64 的黑色或彩色小窗口，随后小窗口内短暂显示 UI 内容，最后才恢复为 1244×700 正式窗口。曾经尝试透明窗口、延迟 Reveal、Python Splash、NativeWindowGate、窗口焦点调整等方案，复杂度不断上升，问题始终没有真正解决。
- **最终根因**：项目把启动窗口配置为 1×1，但 Godot 4.7.2 在 `SceneTree` 初始化时已将主窗口最小尺寸固定为 64×64，项目配置无法突破这个引擎侧下限，于是「1×1」实际变成「64×64」；同时主场景在 UI 初始化完成后才通过延迟调用恢复窗口尺寸，临时小窗口因此获得被显示的机会；外部 `NativeWindowGate` 还存在 `ctypes.wintypes.WNDENUMPROC` 异常（该属性在 Python 3.10+ 的 `ctypes.wintypes` 中不存在），未能发挥预期作用。以上历史补丁叠加，使启动架构过度复杂。需要区分因果层级：这是偏离引擎正常启动流程的项目级启动设计，并非已证实的 Godot 引擎缺陷；外部遮罩失效只是叠加的额外环节，不能当作最初产生 64×64 窗口的原因。
- **最终修复**：回归 Godot 标准启动方式。`project.godot` 直接设置初始窗口尺寸为 1244×700，保留 1600×900 的视口设计基准与 G3 自定义无边框窗口；移除透明启动窗口及逐像素透明配置；移除启动阶段的延迟 Reveal、超时兜底和跨进程就绪文件；删除 Python Splash 与 NativeWindowGate；恢复「Python 后端 → WebSocket → Godot 前端」的简单启动链路；启动画面改用 Godot 内建 Boot Splash，底色为深灰蓝。本次共精简约 366 行历史启动机制代码。
- **实际验收**：单次启动观测中，首次检测到的窗口尺寸即为 1244×700，13 秒观测期间没有发生窗口尺寸跳变；Python 后端与 Godot 前端连接正常；正式 UI 与封面内容正常显示。用户已亲自确认 64×64 小黑窗口消失。目前启动过程为先显示 1244×700 深灰蓝窗口、随后进入正式 G3 界面；由于正式界面包含氛围光等动态渲染效果，两个阶段的背景存在视觉差异，这属于当前观察到的启动画面切换，不再属于原来的小窗口故障。
- **保留的架构成果**：保留此前 `main.gd` 的多阶段解耦成果，没有使用历史版本覆盖当前主脚本；全部业务模块、3D 展示、WebSocket 连接、窗口缩放与窗口模式切换逻辑均保留，本次只精简启动相关代码。
- **防复发约束（必须遵守）**：① 启动主窗口尺寸由 `project.godot` 直接确定，不得以 1×1 或透明主窗口配合运行时 resize 的方式伪装启动；② 不得通过 `Window.visible = false` 隐藏 Godot 主窗口；③ 不得未经明确需求与独立论证重新引入 Tk 全屏遮罩、Win32 窗口拦截、延迟 Reveal、跨进程就绪文件或多重超时兜底；④ 遇到启动闪烁，先核对 Godot 官方窗口生命周期、项目初始尺寸与 Git 历史，区分「窗口尺寸跳变」与「Boot Splash → 正式渲染的颜色切换」，坚持先审计再改代码；⑤ 不得为修启动问题覆盖 `main.gd` 的其他未提交改动，也不得破坏既有解耦模块；⑥ 不得为消除轻微视觉差异而未经验证再次堆叠启动补丁。
- **历史判断的证据边界**：初始 Git 版本使用 1600×900 窗口配置，但不能据此断言当初用户必然看到过尺寸跳变；透明小窗最早由谁、因何引入缺乏提交记录，属于未证实的动机推测，后续复盘不得写成既定事实。

## 36. 启动遮幕淡入：消除 Boot Splash 与正式界面的整帧切换（2026-10-29）

- **问题现象**：启动架构回归后小窗口问题已消失，但 Boot Splash 的深灰蓝纯色与正式界面之间是**整帧替换**，观感上像"啪"一下切换，而非平滑过渡。
- **机制根因**：Boot Splash 不是场景节点，而是引擎在 `setup2()` 中一次性设置的 RenderingServer 级 boot image（`main.cpp:3988`，4.7.2），官方**没有提供淡出它的 API**，它也不在场景树内，`_ready` 里无法访问；同时 `_ready()` 是单帧阻塞（构建 3D/UI 期间没有任何帧被 present），所以第一帧会整块替换掉 splash。由此确定唯一可行路线：**让主场景首帧长得就跟 splash 一样，再从首帧之后开始动画**。
- **为何不采用"仅统一背景色"**：三个分区各有独立背景色板——GAMES 用 `ColorRect` + `game_background.gdshader`（冷灰蓝 `#0E1218`→`#1D2530`）、MOVIES 用 3D `cinema_ambient`（暖棕黑 `#080505`→`#241A0F`）、SYSTEM 用 3D `game_ambient`（亮蓝 `#0E2045`→`#224278`）；而启动分区由用户设置决定（默认 games）。单一 splash 颜色无法同时匹配三者，且只改颜色也消不掉"细节与运动突然出现"的跳变。
- **实施方案**：主场景内一次性遮幕淡出。`project.godot` 的 `boot_splash/bg_color` 与 `main.gd` 的 `STARTUP_VEIL_COLOR` 统一为 `Color(0.055, 0.070, 0.095)`（GAMES 底色）；`_ready()` 末尾调用 `_start_startup_veil()`，新建 `CanvasLayer(layer=120)`（高于 UI 层 10 与分区遮幕层 110）+ 全屏 `ColorRect`（`MOUSE_FILTER_STOP`，遮幕期间阻止误点击），0.45 秒 `SINE / EASE_OUT` 淡出后 `queue_free()` 整个 CanvasLayer，交互随之恢复。
- **关键时序（曾写反，已修正）**：必须**先创建完全不透明的遮幕，再 `await RenderingServer.frame_post_draw`，最后才创建 Tween**。若先 await 再建遮幕，首帧会露出完整 UI（白闪一帧）；若在 `_ready` 中同步创建 Tween，Tween 会在同一帧推进，首帧即半透明。两者都会破坏衔接。
- **实测验收**：单次启动中，首帧为 `1244×700`、唯一色数 `1`、颜色 `#0E1218`，即整个窗口被纯色遮幕完整覆盖，无 UI 闪现；4.2 秒 296 个采样点内窗口宽高恒为 `1244×700`，无尺寸跳变；淡出自首帧后约 395 ms 开始，可见变化约 340 ms 结束，曲线单调上行、无过冲与亮度尖峰；约 3.7 秒处的二次抬升是封面陆续解码所致，与遮幕无关（遮幕不等待数据）。日志 3 行，无 WARNING 与异常。
- **改动与边界**：共 2 个文件、`+28 / −2`（`project.godot` 1 行配色，`main.gd` 两个常量 + 一个自包含函数 + 一行调用）。未改动窗口初始尺寸、未重新引入透明小窗/外部 Splash/NativeWindowGate/延迟 Reveal；封面入场动画、氛围光与分区着色器、主题控制器、WebSocket 与全部业务模块均未触碰，`main.gd` 解耦结构保持不变。
- **已知限制**：遮幕只负责衔接，不等待数据——淡出结束时封面可能仍在解码，表现为随后几秒的陆续浮现，属预期表现。淡出是否"自然"属主观判断，需用户目视验收（动画每次启动只播一次）。
- **排查方法留痕**：用 `PrintWindow` 截图验证启动画面时，目标位图必须与窗口同尺寸；用小于窗口的位图会返回背景填充色（本次曾因此误判"遮幕未淡出"）。采样窗口也需覆盖整段启动期（`_ready` 阻塞约 0.4–1.5 秒），否则容易把"淡出尚未开始"误读为"没有淡出"。

## 40. WB05｜CRT / VHS 游戏封面阵列成像入场（2026-10-30）

- **目标与最终时序**：首次海报墙构建时，真实封面解码完成后才进入成像；按网格顺序以 130ms 间隔逐张启动，单卡实际时长 960ms，动画重叠播放。Shader 使用单卡 HTML 的 520ms 内部时间轴，由 `game_section.gd` 做 `520 / 960` 时间映射。后续排序、搜索、滚动与重建不重复播放冷启动动画，沿用原有弹簧和交互。

- **用户验收**：用户确认上移对齐后容器感消失、960ms 节奏合适；随后确认去除倾斜并恢复受控辉光后没有明显 BUG；最新风格强化已在用户本机安装，反馈“效果不错”。这是当前用户确认的已安装状态，不由补丁文件名或旧 ZIP 静态内容推断。

## 45. COMICS Experiment A 爆发—显像边缘磷光衔接与颗粒尺度修订（2026-10-31）

- **用户反馈**：通电爆发已经有明显表现力，但水平信号爆发与封面中心展开之间割裂；封面展开边缘缺少磷光 / 荧光；RGB 颗粒过大；“颗粒强度”参数含义不清。
